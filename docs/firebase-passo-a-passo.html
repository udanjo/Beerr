Firebase do BeeRR, passo a passo

Um único projeto para você e sua esposa. Cada um entra com o próprio e-mail e só enxerga os próprios treinos.

1. As três peças

Authentication
Responde "quem é você?". Guarda os e-mails e senhas. Você já criou as duas contas aqui.
Firestore
É o banco onde ficam os planos e treinos. Não tem tabelas: tem "pastas" (coleções) com "fichas" (documentos).
Regras de segurança
Dizem "quem pode ler e gravar o quê". É o que impede um de ver os dados do outro.

2. Como os dados ficam separados

Existe uma pasta chamada users. Dentro dela, uma subpasta para cada pessoa, identificada pelo UID (um código que o Firebase gera para cada conta, tipo k3Jd9xQ…).

users
 ├─ k3Jd9xQ…   (UID do usuário A: você)
 │    ├─ plans       seus planos
 │    └─ sessions    seus treinos feitos
 └─ Zp81mTa…   (UID do usuário B: sua esposa)
      ├─ plans
      └─ sessions
Quem cria essas pastas? O próprio app, no primeiro backup de cada pessoa. Você não precisa criar nenhuma coleção nem documento à mão.

3. Por que o e-mail não serve como id

A regra de segurança compara a pasta com o UID de quem está logado. O app sabe o UID de quem entrou, mas a regra padrão do Firebase não funciona bem usando o e-mail como nome de pasta.

Usado como nome da pastaResultado
UID (k3Jd9xQ…)Funciona. É o padrão do Firebase e o que o app vai usar.
E-mail digitado à mãoA regra não reconhece a pasta e bloqueia o acesso. Também dá margem a erro de digitação.
O que fazer com o que você criou à mão: pode apagar a coleção users com os e-mails no console do Firestore. Ela só atrapalha. O app cria a certa sozinho.

Se quiser ver os UIDs: console do Firebase → Authentication → Usuários, coluna "UID de usuário". Não precisa copiar para lugar nenhum.

4. Precisa de uma tela de cadastro no app?

Não. As duas contas já existem no Authentication, então o app só precisa de uma tela de login (e-mail e senha). Isso é mais seguro e mais simples:

  • Cadastro aberto deixaria qualquer pessoa que tivesse o app criar conta no seu projeto.
  • Com as contas criadas por você, ninguém mais entra.
  • Se sua esposa não souber a senha que você definiu para ela, no login haverá "Esqueci minha senha": ela recebe um e-mail e define a própria. Também dá para você enviar essa redefinição pelo console.

5. O que o Firestore pede ao ser criado

Ao criar o banco, o assistente pergunta coisas como o nome/ID do banco, o local e o modo de segurança. Isso é só a configuração do banco e não tem relação com usuários. Pode deixar o nome padrão. Para o local, escolha São Paulo (southamerica-east1) se aparecer, porque não dá para mudar depois. Para o modo, escolha produção.

O que o console exibir de diferente do que está aqui, tire um print ou copie o texto e me mande. Os nomes dos menus mudam de vez em quando.

6. O que falta fazer

  1. Apagar a coleção users criada à mão com os e-mails (passo 3).
  2. Publicar as regras. No Firestore, aba Regras, cole o texto abaixo e clique em Publicar: 
    rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{uid}/{document=**} {
      allow read, write: if request.auth != null && request.auth.uid == uid;
    }
  }
}
    Em português: "dentro de users/ALGUM-UID, só pode ler e gravar quem estiver logado e tiver exatamente esse UID".
  3. Bloquear cadastros novos. Em Authentication → Configurações, desative a criação de contas, se a opção existir.
  4. Registrar o app web. Engrenagem → Configurações do projeto → Seus apps → ícone </>. Nome beerr, sem Hosting. O console mostra um bloco com apiKey, authDomain, projectId, storageBucket, messagingSenderId e appId.
  5. Me passar esse bloco. Eu crio o arquivo .env.local (que fica só no seu computador, fora do Git). Esses valores não são segredo, a proteção são as regras do passo 2. Nunca mande as senhas das contas.

7. Como vai funcionar no dia a dia

  1. Cada um abre o app no próprio celular e entra com e-mail e senha uma única vez. O app lembra.
  2. Os treinos são gravados no celular, mesmo sem internet.
  3. Quando o celular estiver no Wi-Fi, o app copia o que mudou para o Firebase, na pasta daquela pessoa.
  4. Se trocar de celular ou reinstalar o app, é só entrar de novo: os planos e treinos voltam do Firebase.
